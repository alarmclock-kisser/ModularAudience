Deterministic Source Separation — Packets A & B

Context

Two handoff docs (DeterministicSeparation.md, SOURCE_SEPARATION_HANDOFF.md) describe a deterministic STFT/HPR/MDL/IS-NMF separator with standalone-but-unwired advanced cores: CQT, pYIN, ILRMA helpers, and 16 instrument profiles + 3 ensemble modes. The production pipeline and dialog still only run the Automatic path; AnalyzeAsync throws NotSupportedException for every advanced option or non-Automatic ensemble.

  • 16 profiles + InstrumentEnsembleMode (Automatic/ProfilesOnly/ProfilesAndAutomatic): present (inside settings file).

  • Dialog: only 10 baseline controls; no advanced section; stale check uses record !=.
  • Guard in AnalyzeAsync (lines ~12-16): rejects UseCqtAnalysis/UseCqtSynthesis/UsePyin/UseIlrma/non-Automatic.
  • Tests: all 4 classes present incl. UnconnectedAdvancedOptionsAreRejectedInsteadOfIgnored.

Plan — this session: Packet A (UI) + Packet B (guided grouping)

Packet A — Settings/UI plumbing

  1. Replace current.Settings != settings with semantic IsEquivalentTo in the dialog's stale check.
  2. Add advanced/ensemble section using tabs (avoid overly tall window):
    • Tab "Advanced DSP": checkboxes UseCqtAnalysis, UseCqtSynthesis, UsePyin, UseIlrma (all disabled + labeled "pending" until their DSP packet lands — B/C/D/E not done yet this session).
    • Tab "Ensemble": ensemble-mode DomainUpDown (Automatic/ProfilesOnly/ProfilesAndAutomatic), CheckedListBox of the 16 catalog profiles, and a note that guided grouping is enabled in Packet B.
    • BPO DomainUpDown (12/24/36) + CQT minimum Hz numeric (pending/disabled).
    • pYIN min/max Hz numeric (pending/disabled).
    • ILRMA iterations/components numeric (pending/disabled).
  3. Wire ALL controls in .Designer.cs; only add data items (profile list, BPO values) at runtime.
  4. Populate settings via immutable profile selection (ImmutableArray), not a mutable shared list.
  5. Invalidate analysis on every option/profile change incl. committed ItemCheck state; disable inputs during jobs.
  6. Keep progress/status/cancel/close and output-memory estimate intact.

Packet B — Guided instrument grouping (independent of advanced transforms)

  1. Use profile priors (pitch bounds, SpectralWeight/brightness, harmonic/percussive/noise evidence) to assign weighted component membership; avoid name-only or crude hard frequency cuts.
  2. Extend existing integer-Components groups with per-component weights; sum memberships ⇐ 1 per component across output groups.
  3. Masks must actually use those weights; energy/evidence values reflect fitted weights.
  4. ProfilesOnly → requested profile targets + Residual. ProfilesAndAutomatic → profiles + extra stable automatic groups, no double counting.
  5. Use >= as many candidate NMF components as requested profiles (respect MaxComponents).
  6. Keep old Automatic path byte/tolerance-equivalent with flags off.
