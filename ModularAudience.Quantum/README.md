# ModularAudience.Quantum

Standalone `net10.0` quantum-pattern subsystem. It has **no WinForms or audio-project dependency**.
The projects follow this repository's existing flat layout, rather than introducing a second `src`/`tests` layout:

```text
ModularAudience.Quantum/                  # Circuits, execution, mapping, DI
ModularAudience.Quantum.Tests/            # Cross-platform MSTest tests and HTTP mocks
ModularAudience.Forms/Quantum/            # AudioObj DSP bridge
ModularAudience.Forms/Modules/
  DrumRollEditor.Quantum.cs               # Per-row generation, cancellation and commit
ModularAudience.Audio.Tests/
  QuantumDrumRollTests.cs                 # DSP, UI and export integration tests
```

## Quick start: offline generation

```csharp
using Microsoft.Extensions.DependencyInjection;
using ModularAudience.Quantum.Abstractions;
using ModularAudience.Quantum.Extensions;

var services = new ServiceCollection();
services.AddQuantumPatterns(); // Local simulator; never silently submits paid cloud jobs.
// For reproducible measurements instead:
// services.AddLocalQuantumSimulator(options => options.Seed = 42);

using var provider = services.BuildServiceProvider();
var quantum = provider.GetRequiredService<IQuantumPatternService>();

var pattern = await quantum.GenerateBreakbeatAsync(
    qubits: 4, shots: 1024, cancellationToken: cancellationToken, stepCount: 16);
```

The builder and orchestration service are safe to reuse for concurrent requests. The local client implements
the same `IQuantumClient` contract as the IBM client. It performs state-vector simulation of H, X, CX and numeric
Ry gates for 4–16 qubits, including interference; it is not just a random bitstring generator. Unsupported QASM
instructions, mid-circuit measurements and mismatched registers are rejected. This is offline execution, not
literally zero-time execution. A fixed seed reproduces counts across repeated requests, independently of job IDs.

### OpenQASM 2 and 3

```csharp
using ModularAudience.Quantum.Models;
using ModularAudience.Quantum.Services;

string qasm = new OpenQasmCircuitBuilder(4, OpenQasmVersion.Version2)
    .WithSuperposition(0)              // h q[0];
    .WithEntanglement(0, 1)            // cx q[0], q[1];
    .WithBitFlip(1)                    // x q[1]; anti-correlated measurement outcomes
    .WithRotation(2, Math.PI / 3)      // radians; culture-invariant numeric output
    .Build();
```

The fluent builder is **immutable**: keep the returned builder after each `With...` call.
`WithQubitCount` starts a fresh circuit while retaining the selected QASM version. Measurements are appended
once, at the end. QASM 2 uses `qelib1.inc`, `qreg`/`creg` and `measure q -> c;`. QASM 3 uses `stdgates.inc`,
`qubit`/`bit` and `c = measure q;`.

## IBM Quantum Compute Service

### Credentials and transport

IBM Cloud **API keys are not IAM bearer tokens**. The client can either exchange an API key at the IAM token
endpoint, cache the result and refresh before expiry, or use an externally managed IAM access token directly.
All Quantum API requests send `Authorization: Bearer ...`, `Service-CRN` and `IBM-API-Version`.

```csharp
services.AddIbmQuantum(options =>
{
    options.ApiKey = Environment.GetEnvironmentVariable("IBM_QUANTUM_API_KEY")
        ?? throw new InvalidOperationException("IBM_QUANTUM_API_KEY is missing.");
    options.ServiceCrn = Environment.GetEnvironmentVariable("IBM_QUANTUM_SERVICE_CRN")
        ?? throw new InvalidOperationException("IBM_QUANTUM_SERVICE_CRN is missing.");
    options.Backend = Environment.GetEnvironmentVariable("IBM_QUANTUM_BACKEND")
        ?? throw new InvalidOperationException("IBM_QUANTUM_BACKEND is missing.");
    // For an eu-de instance:
    // options.BaseAddress = new Uri("https://eu-de.quantum.cloud.ibm.com/api/v1/");
    // Or set AccessToken instead of ApiKey (externally managed expiry).
});
```

Do not commit credentials to source control or embed them in the desktop executable. No live jobs are submitted
by the tests. Creating a hardware job may consume your IBM instance allocation or incur charges.

### Important: hardware requires ISA circuits

**The logical H/CX/Ry circuit generated by the default builder is not automatically suitable for a real QPU.**
IBM requires backend-specific ISA gates and physical connectivity. This subsystem is a REST transport and a
logical circuit builder, **not a Qiskit transpiler**. The API does not provide automatic general-purpose
transpilation of arbitrary logical input. Do not switch the default UI service to IBM and expect its logical
circuits to run unchanged.

Transpile the circuit for the selected backend using Qiskit or your own compiler, then execute the resulting
QASM directly. The logical measurement register must still contain the requested 4–16 bits. Physical ISA
circuits can reference more physical qubits than the measured logical width.

```csharp
using ModularAudience.Quantum.Models;

// After registering AddIbmQuantum and building the service provider:
var client = provider.GetRequiredService<IQuantumClient>();
var mapper = provider.GetRequiredService<IQuantumPatternMapper>();
string isaQasm = await File.ReadAllTextAsync("breakbeat.isa.qasm", cancellationToken);

var job = await client.ExecuteAsync(
    new QuantumJobRequest(isaQasm, QubitCount: 4, Shots: 1024, ClassicalRegister: "c"),
    cancellationToken);
var pattern = mapper.Map(isaQasm, job.Counts, job.ExecutionLatency, stepCount: 16);
```

An application with a backend-aware compiler can replace `IQuantumCircuitBuilder` in DI to use the high-level
pattern service with hardware. The mapper and REST client do not need to change.

The client uses documented Sampler V2 jobs (`program_id: sampler`, `params.version: 2`, `params.pubs`,
`params.shots`, `support_qiskit: false`), polls `/jobs/{id}?exclude_params=true` and reads `/jobs/{id}/results`.
The decoder supports single-register count histograms, pure-JSON shot samples, big-endian byte rows and Runtime
`PrimitiveResult`/`DataBin`/`BitArray` wrappers, including bounded zlib/base64 NumPy uint8 arrays. Sweeps and multiple
PUBs are intentionally rejected rather than silently combining unrelated measurements. The result must contain
the requested number of shots.

### Cancellation and resilience

- Every public execution/generation method requires a `CancellationToken`.
- Caller cancellation remains an `OperationCanceledException`; HTTP/job deadlines become `TimeoutException`.
- Defaults: 30-second HTTP timeout, 5-minute total job deadline and 1-second polling interval.
- GET requests retry transient transport errors and HTTP 429/500/502/503/504 at most twice. Backoff honors
  `Retry-After`, with a 60-second per-delay ceiling and the overall job deadline.
- **Job-submission POSTs are never retried**: a lost response must not cause duplicate billable jobs.
- HTTP 401/403 are surfaced immediately. A configured direct access token is not automatically renewed.
- Failed/cancelled jobs and unknown/malformed response states fail explicitly.
- Cancelling or timing out the local wait **does not cancel the remote IBM job**. It may still be queued/running;
  inspect or cancel it in IBM Quantum Platform. A timeout after submission can occur before a job ID is known.
- HTTP responses, clients and streams are disposed. Clients are created exclusively via `IHttpClientFactory`.
  Production registrations disable redirects and reject non-HTTPS credential endpoints.

`System.Text.Json` uses source-generated `JsonSerializerContext` metadata for request/auth/status DTOs and
histograms; variable result envelopes use `JsonDocument`. The library enables AOT compatibility analyzers, and
the Quantum tests disable reflection-based JSON serialization. This avoids reflection-based serialization;
it does **not** make HTTP, JSON DOM parsing, simulation or DSP allocation-free.

## Deterministic breakbeat mapping

Bitstrings use IBM/Qiskit ordering: **q0 is the rightmost bit**. The mapper returns one event for each grid step,
including rests, with contiguous zero-based indices. The default grid has 16 steps; 1–1,024 are supported.

1. Validate equal-width binary keys (4–16 bits) and non-negative counts. Zero-frequency states are omitted.
2. Sort states ordinally, independently of dictionary insertion order, and build their frequency-weighted CDF.
3. Use midpoint quantiles `(((step * stride) % stepCount) + 0.5) / stepCount`, with the first odd stride starting
   at 5 that is coprime to the grid length. This spreads the histogram over the grid without claiming that a
   histogram contains the original temporal order of shots.
4. On even steps q0 controls the main trigger; on odd steps q1 controls the anti-phase/snare trigger. The DTO
   describes a sample-row event, not an instrument identifier; use separate mapper implementations for multi-lane
   instrument assignment if needed.
5. Active velocity is `selectedStateCount / totalShots`; rests have velocity 0.
6. Interpret `(q3 q2)` as a two-bit integer:

   | q3 q2 | Pitch shift |
   |-------|-------------|
   | 00    | -500 cents  |
   | 01    | -200 cents  |
   | 10    | 0 cents     |
   | 11    | +300 cents  |

7. Compute a coupling proxy from the mean absolute pairwise classical phi correlation. Constant-bit pairs
   contribute zero. Map density `d` to stretch `1 + 0.5*d` and cut offset
   `100*d*(numberOfOneBits / qubitCount)` milliseconds.

Measurement histograms **cannot certify entanglement or recover quantum phase**. Correlation is explicitly a
musical control proxy, not a physical entanglement measurement. The X after CX in the generated circuit creates
anti-correlated q0/q1 outcomes; weighted rotations on q2/q3 followed by CX control pitch and slice variation.

For `{"1001":512,"0110":512}`, the exact default trigger indices are **1, 2, 6, 7, 8, 11, 12, 13**. Both states
have velocity 0.5 on active steps, stretch 1.5 and cut offset 50 ms. `1001` maps to 0 cents and `0110` to -200 cents.
The deterministic test checks all 16 complete records, not just their ranges.

Empty/zero-only counts produce neutral rests (velocity 0, pitch 0, stretch 1, cut 0). Invalid data throws instead
of being repaired silently. Returned slices/counts are defensive read-only snapshots, and frequency totals use
64-bit arithmetic.

## Drum Roll integration

`Program.cs` registers the local pattern service and passes it through `WindowMain` to `DrumRollEditor`.
Right-click a sample row and choose **Generate Quantum Pattern...**. The initial UI action uses 4 qubits,
1,024 shots and the editor's complete grid (hits × bars). Reopen the row menu to cancel an active generation.
**Clear Quantum DSP** removes the prepared variants while keeping the row's trigger grid.

For programmatic use, call on the editor's UI thread:

```csharp
await editor.ApplyQuantumPatternToRowAsync(
    rowIndex: 0, qubits: 4, shots: 1024, cancellationToken: cancellationToken);
```

The bridge:

- Uses the existing `AudioObj` and `SampleModellerDsp` APIs, not fictitious fluent audio methods.
- Copies the source and prepares frame-aligned cuts, pitch-preserving pitch shifts (`cents / 100` semitones),
  duration stretch and velocity gain on a worker thread.
- Clamps an excessive cut to the last complete source frame, leaving at least one frame.
- Reuses identical prepared variations; caps retained prepared PCM at 256 MiB.
- Makes the same prepared samples available to the playback scheduler and WAV/mix export. Export resamples
  source-rate PCM to the output rate instead of changing its pitch/duration. Quantum DSP preparation and network
  calls never run inside the scheduler/audio callback; existing output resampling, gain and limiting remain in
  the sample-provider chain.
- Respects row locks, rejects concurrent generation and stale results after a sample/grid change, cancels on
  editor close, and disposes discarded/replaced prepared samples.
- Clears quantum DSP for edited/randomized rows and prunes removed rows or resized grids.
- Keeps original sample PCM unchanged. All new UI labels, errors and warnings are in English. Provider/framework
  exception messages are not displayed verbatim, so localized text or credentials cannot leak into the warning.

## Quantum Beat Engine dialog (ModularAudience.Forms)

Right-click a multi-selection (2–32 samples) in an audio collection and choose
**Generate Breakbeat → Quantum Beat Engine (IBM®)**. The dialog is modeless: other collections, editors and
playback stay interactive while connecting, simulating, submitting IBM jobs or rendering audio.

- **MenuStrip:** `Connection | Edit | Circuit | Pattern | Output | Help`.
- **Connection:** API key or IAM bearer token plus instance CRN, regional REST endpoint, backend, timeouts and
  Qiskit Python path. *Test / Connect* performs read-only backend discovery only; nothing is submitted. IBM cloud
  jobs additionally require the explicit `Allow IBM cloud jobs` checkbox, which is always unchecked after loading.
- **Circuit designer:** visual gate canvas (click wires to select control/target, click columns to select rows),
  H/X/CX/Ry gate table, presets, randomization (layers, Hadamard/CNOT probability, rotation range, seed), width 4–16
  with optional width inference, and live logical OpenQASM 2/3 output.
- **Rhythm + DSP:** bars, resolution, arrangement, swing, density, quantum-driven velocity, ghost notes, note
  duration, pitch, time-stretch, varispeed, slice cut, reverse, fitting/truncation, tail and gain controls.
- **Sample tracks:** per-track trigger qubit, invert, density, step offset, gain and pitch columns.
- **Results:** breakbeat sequence diagram (PictureBox), note-timing table with start/duration in ms, measurement
  counts, logical QASM and hardware ISA QASM. `Response delay` reports measured end-to-end execution latency.
- **Edit:** Save / Load / Rename plus Delete (named preset) or Reset (unsaved current setup) through a modeless
  library window with explicit overwrite/delete confirmation checkboxes.

Persistence lives in `%APPDATA%\ModularAudience\QuantumBeatEngine` as versioned JSON: `workspace.json` (current
setup including the auto-save checkbox, window size and tab), `Experiments\experiment-*.json` (named setups, no
audio PCM), `Connections\connection-*.json` (credentials protected with Windows DPAPI for the current user, never
plaintext) and `Recovery\workspace-*.json` (used automatically if `workspace.json` is corrupt; the broken file is
kept until an explicit reset). Writes are atomic (temp file + rename). The workspace is saved on close even when
auto-save is off; with auto-save on it is debounced after each edit and named presets are refreshed. Loading a
workspace never opens a network connection or restores cloud-job permission.

Local generation uses the state-vector simulator (`QuantumArrangementMapper` picks one shared weighted measurement
per grid step so cross-track correlations survive remapping); *Remap counts* re-runs mapping without any API call.
Hardware runs invoke the embedded Qiskit helper (`TranspileCircuit.py`) with circuit/target metadata on stdin —
no credentials reach Python or the command line — then submit the resulting ISA QASM over REST.

## Tests

From the solution directory:

```powershell
dotnet test ModularAudience.Quantum.Tests/ModularAudience.Quantum.Tests.csproj
dotnet test ModularAudience.Quantum.Tests/ModularAudience.Quantum.Tests.csproj --collect:"XPlat Code Coverage" --settings ModularAudience.Quantum.Tests/coverage.runsettings
dotnet test ModularAudience.Audio.Tests/ModularAudience.Audio.Tests.csproj --filter FullyQualifiedName~QuantumDrumRollTests
```

The Quantum project/tests are platform-independent; the DSP/UI integration tests require Windows. Coverage
reports are written to the ignored `ModularAudience.Quantum.Tests/TestResults` directory and include the Quantum
assembly only, excluding generated serialization/regex code. The required core-code line-coverage target is >90%.

Tests cover QASM 2/3 syntax and invariant angles, deterministic mapping and boundaries, real local matrix
simulation, DI/provider substitution, IAM caching/refresh, Bearer/CRN/version headers, HTTP 200/401/500, retry
budgets, timeout/cancellation, malformed job/results data, shot totals and supported result formats. HTTP tests
use `MockHttpMessageHandler` and never require credentials or contact IBM.
